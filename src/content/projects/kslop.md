## What This Is Really About

KSLOP is a radio station, but the radio station isn't the point.

The point is the question: **can you organize a team of AI agents to build, operate, and evolve a real product — autonomously?** Not a toy demo. Not a one-shot code generation trick. A product that requires continuous content production, creative decisions, technical infrastructure, and real-time operations, running indefinitely.

A radio station turns out to be a perfect test case. It demands every capability you'd want to stress-test: sourcing information from the open internet, distilling it into something worth listening to, writing scripts with a specific voice and editorial sensibility, generating spoken audio, composing music, assembling a final broadcast file, scheduling it, and streaming it to actual listeners. If a team of agents can run a radio station, they can probably run a lot of things.

## The Agent Syndicate

KSLOP is staffed by a small founding team of AI agents, each with a defined role:

- **SWE** builds all technical systems — the streaming pipeline, the website, the infrastructure
- **Writer** creates show identities, writes episode scripts, and develops brand copy
- **Web** builds and maintains the station's public-facing website
- **Marketing** handles social media promotion and audience building

A **Prime** agent dispatches work, reviews output, and keeps things moving. The human (me) acts as CEO — setting direction, approving spending, and providing editorial guidance when needed.

The agents coordinate through a shared workspace and an MCP server that exposes tools for managing station content. The idea is that they can operate with increasing autonomy over time. Start conservative — human reviews everything — and gradually let go as trust is established.

## Why a Radio Station

I wanted something that couldn't be faked. A static website can be generated in one shot. A radio station can't. It requires:

- **Continuous production** — new content every day, not a one-time generation
- **Creative judgment** — choosing what's worth covering, what angle to take, what tone fits
- **Technical depth** — audio pipelines, streaming protocols, real-time scheduling
- **Operational persistence** — the stream has to keep running, the schedule has to be maintained
- **Multiple disciplines** — writing, engineering, design, marketing, all interacting

If you want to learn how agents collaborate on something real, you need a product that's genuinely hard to run.

## The Format: Mergecasts

The flagship show format is the **mergecast** — a condensed audio digest of the most important content circulating in a given domain (tech, finance, internet culture).

The internet produces a massive volume of podcasts, YouTube videos, blog posts, X threads, Reddit discussions. Nobody can keep up. A mergecast distills all of it into a ~30-minute show hosted by an AI anchor with a distinct personality. Think of it as a daily briefing generated by agents who never sleep and never get bored of reading Reddit.

## How Content Flows

The production pipeline mirrors how a real radio station operates, except every step is handled by an agent:

1. **Source** — crawl social media, podcasts, YouTube, blogs for trending content
2. **Distill** — condense raw signals into a topic brief
3. **Script** — write a show script for a specific anchor and show identity
4. **Voice** — generate audio via ElevenLabs TTS
5. **Score** — generate music, transitions, sound effects
6. **Assemble** — stitch voice, music, and ads into a final broadcast file
7. **Schedule** — slot into the programming grid
8. **Broadcast** — stream to listeners

## What I'm Learning

It's early, but a few things are already clear:

**Agent specialization matters.** Giving each agent a clear role and a narrow mandate produces better results than asking one agent to do everything. The SWE agent builds systems. The Writer agent writes. They don't step on each other.

**The coordination layer is the hard part.** Getting individual agents to do tasks is straightforward. Getting them to collaborate — passing context, maintaining shared state, resolving conflicts — is where the real challenge lives.

**Autonomy has to be earned, not declared.** Starting with full autonomy is a recipe for expensive mistakes. The current model is conservative: human approves spending, reviews editorial decisions, and provides course corrections. The agents earn more freedom as they demonstrate reliability.

## Current Status

The infrastructure is built and running. Phoenix app, Liquidsoap streaming engine, Nginx for HLS delivery, PostgreSQL for data — all orchestrated via Docker Compose. The station website is functional. An MCP server gives agents programmatic access to manage shows, episodes, and schedules.

What's next: producing actual show content (the first mergecast episode), deploying to production, and seeing how far the agents can run the station without me.
